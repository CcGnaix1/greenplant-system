## 三、启动步骤（按顺序）

> **命令写法约定**：以下命令一律用**正斜杠路径**（`C:/Plant/...`），含空格的路径**加英文双引号**，
> 这样 cmd 和 Git Bash 两种终端都能直接粘贴执行。
> 唯一例外是设置 `JAVA_HOME`（见步骤 3）：cmd 用 `set`、Git Bash 用 `export`，**两者不通用**。

### 步骤 1 · 启动 MySQL

MySQL 已注册为 Windows 服务 **`MySQL80`**，且设为**开机自动启动**，通常无需手动操作。
若需手动控制（例如服务意外停止）：

```bash
net start MySQL80      # 启动
net stop  MySQL80      # 停止
sc query  MySQL80      # 查看状态
```

- 账号 `root` / 密码 `123456`，端口 `3306`，库名 `plant_db`
- 配置来自 `C:\ProgramData\MySQL\MySQL Server 8.0\my.ini`（`datadir` / `port` / `basedir` / `log-error` 都写在这里）
- 错误日志：`C:\Users\10970\mysql-data\mysql-error.log`
- 日志刻意放在**数据目录内**而不是项目目录下，否则 mysqld 会一直握着项目目录的文件句柄，
  导致后续 `mvn clean` 报「另一个程序正在使用此文件」

> **如果把项目拷到别的机器**：该机器上可能没有 MySQL80 服务，需要先注册（**需管理员权限**）：
>
> ```bash
> "C:/Program Files/MySQL/MySQL Server 8.0/bin/mysqld.exe" --install MySQL80 \
>   --defaults-file="C:\ProgramData\MySQL\MySQL Server 8.0\my.ini"
> net start MySQL80
> ```
>
> `my.ini` 内容见本项目同路径文件；若数据目录不同，改 `my.ini` 里的 `datadir` 即可。

> **改配置后重启生效**：`net stop MySQL80 && net start MySQL80`

**首次运行需导入数据库**（按此顺序执行）：

| 顺序 | 脚本 | 作用 | 可重复执行 |
|---|---|---|---|
| 1 | `db/schema.sql` | 建库 + 建 10 张表 | ✅ `IF NOT EXISTS` |
| 2 | `db/seed.sql` | 演示数据（6 品种 / 用户 / 档案 / 养护记录等） | ⚠️ **会清空全部 9 张表** |
| 3 | `db/plant_knowledge_add.sql` | 品种扩充 6 → 20 种 | ✅ `ON DUPLICATE KEY UPDATE` |
| 4 | `db/symptom_dict.sql` | 症状字典（9 条，诊断用） | ✅ `ON DUPLICATE KEY UPDATE` |

```bash
cd "C:/Plant/绿植智能养护系统/plant-manage"
"C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -p123456 plant_db < db/schema.sql
"C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -p123456 plant_db < db/seed.sql
"C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -p123456 plant_db < db/plant_knowledge_add.sql
"C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe" -uroot -p123456 plant_db < db/symptom_dict.sql
```

> **⚠️ `seed.sql` 开头有 `DELETE FROM` 全部 9 张表**，重复执行会抹掉用户自己建的档案和记录。
> `symptom_dict.sql` 刻意没并进 `seed.sql` 就是为了避免这个连带清空。

> **为什么品种必须有 20 行**：品种识别是**闭集分类**，类别数 = `plant_knowledge` 行数。
> 模型按这 20 个类目训练，库里少了行会导致前端拿到的 `knowledge_id` 查不到品种，
> `desc` 和知识库详情都会空。

### 登录 / 注册（2026-09-29 真实登录；2026-10-03 开放自助注册）

登录页输入手机号 + 密码，后端 `POST /auth/login` 校验后签发 JWT。
**密码在库里是 PBKDF2 哈希**（`PasswordUtil`，JDK 自带，无第三方依赖），不再是明文。

登录页现在有「登录 / 注册」切换：**注册可自定义手机号 + 密码**，走 `POST /auth/register`。
后端会**为该用户自动创建一个独立家庭**并设为 owner，注册成功直接返回 token（免二次登录）。
账号沿用手机号（`^1\d{10}$`），密码 6–32 位。

- 重复手机号 → 返回 **`{code:4012}`「该手机号已注册」**（刻意不复用 4010/4011，
  避免前端误判成登录态失效）
- 不留空 `family_id`：否则 `FrontService.familyInfo` 会兜底成演示家庭（family_id=1），
  新用户会看到别人的成员/数据

|---|---|---|
| `13800000001` | `123456` | 家庭 owner，**演示数据都在这个账号下**（4 个植株档案）→ 演示推荐用这个 |
| `13800000002` | `123456` | 家庭成员（妈妈） |
| `13800000003` | `123456` | 家庭成员（爸爸） |
| `13900000001` | `plant2026` | 2026-09-29 新建，**名下无数据**，用于演示「新用户登录」 |

鉴权已开启：未登录访问业务接口返回 `{code:4010}`，小程序会清 token 并跳登录页。
**例外**：`/auth/**`（登录本身）与 `/species/recognize` 在白名单里。

- 上表账号是**演示预置数据**（`db/auth_accounts.sql`）；用户也可在登录页**自助注册**

- 改密码：用 `tools/PwTool.java` 生成哈希（它复用生产的 `PasswordUtil`，做过往返校验），
  再 `UPDATE user SET password='...' WHERE phone='...'`。
  命令见该文件头部注释。**不要直接写明文** —— 虽仍能登录（verify 兼容明文并在登录后
  自动升级），但会短暂以明文落库。
- JWT 密钥在 `application.yml` 的 `plant.jwt.secret`，**必须 ≥32 字节**（HS256 要求
  256 位），否则签发时抛 `key byte array is N bits which is not secure enough`。

## 六、已知坑（改代码前必读）

1. **MyBatis-Plus 3.5.5 与 Spring Boot 4.1 不兼容**
   `mybatis-plus-spring-boot3-starter` 的自动装配引用了 Boot 4 中已迁移的包，在 Boot 4.1
   下静默失效，表现为启动报 `No qualifying bean of type ...Mapper`。
   已通过 `config/MybatisPlusConfig.java` 手动声明 `SqlSessionFactory` + `@MapperScan` 绕过。
   **不要删这个类**，也不要指望 MP 的自动配置生效（分页插件需自行注册）。
   同理 Boot 4 移除了 `RestTemplateBuilder`，改用原生 `SimpleClientHttpRequestFactory`。

2. **`pom.xml` 显式加了 `jackson-databind`**，因为 Boot 4 下它不再是编译期传递依赖。

3. **AI 服务未启动时后端会回退 mock**（`FrontService.mockRecognize()`），
   保证前端流程不中断。所以「识别结果看起来不对」时，先确认 `/health` 的 `isMock` 是否为 `false`。

4. **推理服务的路径守卫**：`recognizer.py` 的 `resolve_upload_path()` 只允许
   `C:\Plant\upload` 下的文件，越界返回 403。这是防任意文件读取的**有意设计**，
   直接拿数据集路径去 `POST /recognize` 会被拒。

5. **Python 脚本不要打印 emoji**：Windows 控制台默认 GBK，
   `print("✅ ...")` 会抛 `UnicodeEncodeError` 中断进程。

6. **中文路径一律用 Python `pathlib` 创建**，别用 shell 循环
   （会混入不可见的私有区字符 `U+F00D`）。

## 七、快速自检

三个服务都起来后，按以下顺序验证：

```bash
# 1. AI 服务就绪且非 mock
curl http://127.0.0.1:5000/health          # 期望 "isMock":false

# 2. 后端在跑
curl http://127.0.0.1:8000/api/plant/list  # 期望 {"code":0,...}

# 3. 端到端识别（换成 upload/recognize 下实际存在的任意一张图）
curl -X POST http://127.0.0.1:8000/api/species/recognize -F "image=@C:/Plant/upload/recognize/1790591866530.jpg"
```

第 3 步返回的 `data.isMock` 应为 `false`，且 `data.candidates[0]` 给出品种与置信度。
